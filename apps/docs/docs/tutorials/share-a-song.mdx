# Share and import songs

Out of your library, and into it.

Two different things leave by the same button, and telling them apart is most of
this page. A **download** is a page or a picture — something to print, to pin on
a wall, to send to somebody who has never heard of Achordeon. An **export** is
the song itself: the words, the chords and the render settings as data, made to
be read back. One of them is finished when it lands; the other is still a song.

The way in is one screen whatever the thing travelled as — a file you picked, a
file dropped on the window, or a link you tapped — and it always says what it
would do before it writes anything.

## 1. Select the songs

Everything out of the library starts in <AppLink to="songs">Songs</AppLink>. Tick
the rows you want. The tick is a separate gesture from opening a row, so the
selection survives scrolling, searching, and ticking some more.

With nothing ticked the bar acts on **the song you are looking at** — the one
drawn in the pane beside the list — so one song needs no ticking at all. The
tooltip says which it means: <Ui id="songs.downloadOne" /> against a focused
song, <Ui id="songs.downloadSelected" /> once rows are ticked.

A row also carries its own <Ui id="explorer.download" />, and that one means
**that row** whatever is ticked elsewhere. It sits on the row while the list is
wide, and folds behind the row's `⋯` while it is narrow — the same icon either
way.

Songbooks go out the same way from <AppLink to="songbooks">Songbooks</AppLink>,
with one thing worth knowing first: **a book drags its songs along**. A book is
an ordered list of references, so a file with the book and none of the songs
would import an empty book onto exactly the machine you were sending it to.
And <Ui id="songbooks.allSongs" /> is not a record — picking it means the whole
library, so it contributes every song and no book.

## 2. Press Download

The tray with the arrow pointing down, in the row of bulk actions beside <Ui id="songs.add" icon="+" />.
The one beside it, with the arrow pointing the other way, is Import — the two
wear mirrored glyphs because in and out is the whole distinction left to draw.

It opens a dialog headed <Ui id="download.title" /> for one song, and the same
title with the count in it for several — because the count is what decides what
is on offer: one song can be a page or a picture, several can be a book of pages
or a folder of them.

## 3. Choose export or download

Exporting is the last file row of this dialog, under a sentence saying what it
is for.

The hairline across the list is where the answer changes. Above it are renders —
a page, a picture, a folder of them. Below it is <Ui id="download.data" />, the
song as data, and after that the link. Every row is its own button, so there is
nothing to confirm and no OK: the button that downloads sits beside the text
that explains it, and the choice is one click.

The two below the line are the ones that come back. Read <Ui id="download.data" />'s
own hint before you pick anything else — _the song itself — words, chords and
settings_.

## 4. Copy a link instead of taking a file

The last row is <Ui id="download.link" />, and its button reads <Ui id="download.link.copy" />
rather than Download, because nothing lands on disk. It flips to <Ui id="download.link.copied" />
for a couple of seconds, which is the only acknowledgement a clipboard write
ever gets.

What is on the clipboard is worth being precise about, because almost everybody
guesses wrong: **the song is inside the link.** Nothing is uploaded when you
copy it and nothing is fetched when it is opened.

Two things follow from that, and they are the reason to prefer a link at all:

- **No account, on either side.** There is no server in the story to have one
  with. The sender needs none and the reader needs none.
- **It works offline.** The receiving app already has everything the moment the
  link arrives, so an installed Achordeon opens one with no connection at all.

And it can be refused. When the selection will not fit, the row is greyed rather
than removed and says why: <Ui id="download.link.tooBig" /> Take the Achordeon
file instead: it has no such ceiling.

A songbook offers the same thing, as one option of its own download dialog —
see [Print a songbook](./print-a-songbook.mdx#9-choose-the-format).

## 5. Pick the file format

For **one** song there are two renders:

- <Ui id="download.pdf" /> — a page you can print. It is vector, so the text
  stays text: selectable, searchable, and sharp at any size. The fonts are
  packed into the file, so it looks the same on a machine that has none of them.
- <Ui id="download.png" /> — a picture to share, and the one that comes back: a
  downloaded picture is both the picture and the song.

For **several**, the same two ideas plus the question of one file or many. So
there are three: <Ui id="download.onePdf" /> puts every song in one document,
one after another; <Ui id="download.zipPdf" /> is a document per song, packed
together; and <Ui id="download.zipPng" /> is a picture per song.

Every render is drawn from the song's own settings, so what you get is the page
you have been looking at all along — its shape, its scale, its columns. See
[Fit a song on one page](./fit-a-song-on-one-page.mdx).

Once a format is picked the dialog stays open and becomes the progress: a
spinner, and — once the total is known — a count that advances as each song is
drawn. The formats are gone while it runs, because the choice is made and
unmaking it mid-render is not on offer. Where the file lands is the browser's
business: Chromium asks, Firefox and Safari drop it in the downloads folder.

:::note[A whole songbook is a different dialog]

A book's Download asks with a format select and then about paper — size,
orientation, margin — because a book is printed rather than looked at. That is
[Print a songbook](./print-a-songbook.mdx). And a copy of your **entire**
library, tombstones and device settings included, is not an export at all: that
is Backup, in [Settings](/settings-account/settings.mdx#backup).

:::

## 6. Import: the button, a file dropped on the page, or a link

Three ways in, and all three end at the same preview.

- **The Import button.** In Songs it is <Ui id="songs.import" />, the mirrored
  tray beside Download; in Songbooks, <Ui id="songbooks.import" />. It opens
  the file picker, and it takes several files at once.
- **A file dropped anywhere on the window.** Not on a target — the whole window
  is one. Drag a file over Achordeon and the page dims to say <Ui id="import.dropTitle" />,
  with a line under it saying what it will take: <Ui id="import.dropHint" /> The
  drop works on every screen, including the ones that have no Import button at
  all, so a file can be dropped on Settings or mid-performance.
- **A link.** Tapping one opens the preview wherever you land, filled in
  already. It needs no route and no page of its own, which is why it works on a
  cold boot and on an app that was already open.

## 7. Read the preview

Nothing is written until you press <Ui id="import.confirm" />. The dialog exists
to answer one question first — what would this file do to my library — because a
file that silently overwrote nineteen songs on account of the twentieth would be
indefensible.

The first line is the size of it — how many songs the file holds, and how many
songbooks. Under it come the things worth knowing before you agree, each
appearing only when it applies:

- **Fonts this device has not got**, by name. A file names the fonts its songs
  are set in and never carries the font itself, so this is the only place you
  learn what to go and install. The names are kept in the songs either way:
  [add the font](./add-a-font.mdx) later and those pages come back exactly as
  the sender saw them.

## 8. Decide what happens to songs you already have

If any of the incoming songs are already in your library, the dialog names them
— up to five, then a line counting the rest. Named rather than counted, because
"3 songs already exist" is a number and the answer depends on **which** three. A
song that has been renamed on one side shows both names, the file's and yours.

One answer covers the whole file, under <Ui id="import.legend" />:

- <Ui id="import.replace" /> — the default, because the file is usually the
  newer copy: it is the one you just brought over. Yours is overwritten.
- <Ui id="import.ignore" /> — yours stands and the incoming versions are
  dropped. An import that then looks as though it did nothing did exactly what
  you asked.
- <Ui id="import.new" /> — both survive. The incoming songs are written under
  fresh ids, so they are separate songs from then on and will never collide
  again.

The import file is plain JSON and its shape is published, so anything that can
write text can write one — including a chatbot looking at a photo of a chord
sheet, and that is the [AI import guide](/export-import/ai-import.mdx).
