## Profile

This is where the account is, and it is the only place in the app that is. What
an account is for, and what each tier gets, is its own chapter:
[Account](/account.mdx).

You can manage your login and synchronization in this section:

- Login / logout, and adding a second sign-in method to the same account
- Buttons for Google Drive synchronization
- _Premium:_ switch for real-time synchronization
- Manual sync: back up the whole library to a file, or bring one back in

Sending a few songs to somebody else is a different job. That is
[export & import](/export-import.mdx), and it lives with the songs, because
choosing which songs is the whole act. Settings links there.

:::note[Drive access is asked separately]
Signing in with Google does not hand Achordeon your Drive. That permission is
asked the first time you back up to Google Drive, and it covers only the backup
file itself. See [your account & Google data](/account-data.mdx#google-drive).
:::

## Application

- theme - system, light, dark, _FUTURE: colors_
- dark page - off unless you turn it on. With it on, every song the app draws goes
  light-on-dark while the app itself is dark: performing, watching, and the previews
  in Songs and Songbooks. The **Dark page** button overrides it where it appears:
  in the performing bar for that one performance, in the audience menu for that one
  viewing, and under the songbook pages for that book — the print preview says it is
  no longer showing the print output while it is dark. It is per device, and
  printing, PDFs, downloads and your audience are never touched by it
- language - EN, CS
- usage statistics - off unless you turn it on, and the same switch as the one on
  [Privacy](/privacy.mdx#extra-statistics)
- panel size - one size everywhere, or let each module remember how you sized its
  split view on its own

## Rendering

The renderer allows you to customize the output. There is global setting and scoped one.

[`Songs`](songs/editing.mdx#renderer) scope. The controls are grouped into **Page**,
**Title** and **Chords**:

- _Page_: scale (custom text size, useful for maximizing the page space), columns (for
  really long songs), aspect ratio, padding (the white border around the song), and where
  a song that doesn't fill the page sits, horizontal and vertical
- _Title_: position (on top of the page or sideways up the side), layout (the subtitle
  stacked under the title or inline beside it), and the font the title and subtitle share
- _Chords_: the same colour, size and notation a songbook can set, here for a single song

A single song can override anything. A songbook only carries the shared few below.

:::note[One song, one page]
The render settings exist to make the content fit one page.
:::

`Songbooks` scope:

- chords color
- chords size
- chord notation - English (C, D, B) or German (H for B natural, B for B♭). It changes how chords are **printed**, but your song is left exactly as you wrote it, so switching back changes nothing else. `[H]` has always been understood as B natural whichever you pick — English simply prints it as `B`, so a song that mixes the two spellings comes out in one language either way.
- title font - the face the title and subtitle are set in: the song's own font, a serif, a condensed one or a handwritten one. Set it on a songbook and every song in it follows.

## Backup

Save your whole library, and bring it back later. This is the entire database, not a selection, different from [exporting](/export-import.mdx) a few songs to share.

A backup can live in either of two places, and they are the same backup:

- **a file** you keep wherever you keep files
- **your Google Drive**, if you would rather not hold the file yourself

Bringing one back asks what it should do, because a backup serves two jobs:

- **Add to my library** - the backup's songs and songbooks land beside yours. Where you have both, the newer one wins. Your settings are left alone.
- **Replace everything** - the library goes back exactly as the backup has it. Anything not in the backup is lost, your settings included.

The question is the same whether the backup came from a file or from Drive, and so is the answer.

:::note[Add is the one you usually want]
Replace is for putting a machine back the way it was. If you are after songs from an old backup, Add gets them without touching anything you have written since.
:::

:::note[Backup is not sync]
Sync keeps one library the same on every device you sign in on, continuously, with no file involved. A backup is a copy you make and choose when to bring back. Sync will faithfully copy a deletion to your other devices; a backup is what still has the song afterwards.
:::
