Scan of apps/docs/docs/tutorials/, 10 tutorials + index. The measure used: would a first-time user need this to finish the task? If no, it is reference material and belongs in the section docs.

Cross-cutting problems

1. Rationale voice instead of instruction voice

The dominant sentence pattern across all ten is "X does Y, because Z" — a design memo explaining itself. A tutorial says press this, look at that. Samples:

"Numbering the front matter would make the contents send a reader to page 3 for the first song, which is a number they can only use by counting past two sheets that also claim one." — print-a-songbook:140
"a book of a reprise… the two positions are independent" / "One or the other, never both, and that is a decision rather than a missing checkbox" — print-a-songbook:160
"which is why the button is briefly dead when the dialog opens" — share-a-song:130

This is the single biggest source of length. It is good writing in the wrong document.

2. Implementation vocabulary leaking into a beginner page

IndexedDB, service worker, Progressive Web App, "the fragment", gzip, "a PNG chunk", "schema", "ids", "1200 pixels", jsDelivr, raw.githubusercontent.com, "variable font default instance", "AST"-shaped talk about the parser. None of these are needed to write a song or print a book.

3. The cascade is explained four times

"global, then songbook, then song; the nearest opinion wins" appears in full in fit-a-song §10 (lines 274–282), add-a-font §7 (449–452), build-a-songbook §13 (161–164) and transpose §5 (143–145). Explain once — in the docs — and link.

4. Option catalogues that are reference tables

Aspect-ratio shelves (fit §3), 21 title-page styles (print §4), 7 page-number positions (print §7), the format table (print §10, share §9), All-songs sort orders (perform §2), the four ways in for fonts. print-a-songbook:125 already says "The full list, with a line on each, is in Songbooks" — and then lists them anyway.

5. Failure dialogs enumerated everywhere

update.broken, restore.failedTitle, addFont.indexFailed, import.refused, download.link.tooBig, settings.drive.conflict, library.foreign.heading. A tutorial should hit the happy path; error states are reference.

6. Keyboard-shortcut trivia scattered inline

Alt+, · Alt+= · Alt+] · Ctrl+Y · g then h · 0 · +/-. The app has its own shortcut list (perform §4 points at it). Point there once.

write-your-first-song.mdx

Prose is short and right. The interactive challenge is where it goes long: 12 steps, of which the last 5 teach syntax a first song does not need.
  • KEEP steps 1–7 17–170 — title, subtitle, lyrics, block label, sub-label, second block, first chord. That is a first song.
  • MOVE step 8 172–196 — chords-only line.
  • MOVE step 9 198–222 — inline chords with doubled brackets.
  • MOVE steps 10–11 224–274 — bold and italic. Formatting, not songwriting.
  • CUT step 12 276–301 — escaping a colon so Narrator\: stays a lyric. The tell is at line 6: the file has to import { findLabelDelimiter } from '@achordeon/shared/domain' to grade it. A tutorial step that needs a parser helper to check is a syntax-reference step.

play-to-an-audience.mdx

Nearly right — the task is concrete and the steps are short. Trim only.
  • CUT 92–98 — the three things that stay on stage, each with its reasoning.
  • MOVE 175–193 — the viewer's whole menu enumerated (zoom, chords off, dark page, sideways, own lobby, exit). Show two; list the rest in the docs.
  • CUT 221–229 — step 11, re-sync. "The lobby's current song is stored, not just broadcast" is protocol detail, and the step ends by saying the button usually does nothing.

build-a-songbook.mdx — the model

1170 words, 13 short steps, one idea per step, almost no rationale. This is the voice the other nine should be rewritten into.
  • Only two soft spots: 130–140 (search jumps rather than filters, explained at length) and 150–166 (the cascade again).

Suggested order of work

  1. set-up-a-device — biggest win and it is the first page a user reads. Steps 1–3 + back up + sync.
  2. share-a-song — cut the link internals and the chatbot step; both have docs homes already.
  3. print-a-songbook and perform-from-a-songbook — delete the catalogues and the zoom/gesture detail.
  4. transpose and add-a-font — pull the parser rules and the font-style theory into songs/syntax.mdx and the settings docs.
  5. Cascade — write it once, link it from four places.
  6. write-your-first-song — drop the challenge to 7 steps.
